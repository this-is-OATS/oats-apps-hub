VJ VIZZIES SUITE: READ ME FIRST                                                               v0.3.1
===============================

The show laptop package from Fook'n Oats Enterprises. Two things in one zip:

  VJ VIZZIES/      the clip + fractal player for shows: driven from grandMA3 (sACN universe 5 / OSC 7000), full screen on
                   an extra display (HDMI to an LED processor or projector = the show feed), NDI "OATS VIZ Program" for
                   previs, browser controls on port 8090 (phone, laptop, the PC launcher in windows/) and a small Mac app
                   (the installer, the controls window and a menu-bar health dot with start / stop / restart / logs / open at login).
  OATS NDI HUB/    the camera suite: an NDI multiview + free PTZ control in any browser (port 7080), any UVC webcam
                   (Insta360 Link 2, OBSBOT ...) as an NDI camera WITH PTZ and a protected mic, a display as NDI, tally
                   (phone page, OBSBOT LED, lighting console), OSC input on 7081. Its own READ ME FIRST.txt has the details.
  windows/         the control window for a Windows PC (opens http://<the Mac>:8090 in its own Edge window). Edit the URL
                   at the top of "VJ VIZZIES.vbs" / ".cmd" to this Mac's address.

What the laptop needs
---------------------
1. macOS 14 (Sonoma) or later. Apple Silicon OR Intel: the 2020 Intel MacBook Pro is a supported target. Everything in
   the suite ships native for both: the camera suite and the player are universal binaries (Apple Silicon + Intel),
   nothing to compile and no developer tools needed. The fractal governor lowers the internal render resolution on a weaker GPU so the
   output stays at the frame rate; the HDMI output is always full size.
2. The NDI runtime (/usr/local/lib/libndi.dylib, universal). NDI Tools (free, https://ndi.video/tools/) normally installs it; if not, INSTALL.command installs the bundled copy (asks for your password).
3. Apple Silicon only: Rosetta 2 (the camera / display senders and the NDI helper are Intel code; the Intel NDI library
   does not freeze on fine detail, the Apple Silicon one does):   softwareupdate --install-rosetta --agree-to-license
4. The laptop on the lighting network (cable or the show Wi-Fi), ideally with ONE interface on it.

Install (the .dmg: drag, open, two questions)
--------------------------------------------
1. Download VJ-VIZZIES-SUITE-<version>.dmg from https://oats-apps-hub.vercel.app/vizzies/ and open it.
2. Drag "VJ VIZZIES" onto the "Applications" folder next to it. Open it from Applications.
   First time on a Mac, macOS refuses (the app is not notarized yet): System Settings > Privacy & Security > scroll down
   > "Open Anyway", then open it again. Once per Mac; updates from inside the app do not ask again.
3. The setup window asks two things:
     NDI MACHINE NAME  of this Mac (default: its hostname, upper-cased). Sources appear as "NAME (OATS VIZ Program)",
                       "NAME (Link Cam)". EVERY MAC ON THE NETWORK NEEDS ITS OWN NAME (see "Two machines").
     LIGHTING INTERFACE  en0, en1 ... the one on the lighting / NDI network. NDI is pinned to it, the player accepts
                       sACN / OSC / the controls only from that network (and from the Mac itself) and waits for its
                       address at start.
   Click Install. Click Allow when macOS asks for the camera, the microphone and the local network: the APP asks, so the
   camera senders and the player it starts inherit the permission (no Terminal step any more). If the NDI runtime is
   missing (/usr/local/lib/libndi.dylib), it asks for your password once and installs the bundled NDI 6.3.2 (and
   Rosetta 2 on Apple Silicon when that is missing).
   It installs:  ~/Applications/OATS NDI HUB   and   ~/Applications/VJ VIZZIES, starts everything, and registers itself
   as the login item (com.fooknoats.oatsviz: the app opens at login and starts the hub, the cameras and the player).
4. Update: "Check for Updates..." in the app (it also checks once a day) downloads the next version from the site and
   replaces itself; or drag a newer dmg's app over the old one. The app then updates both installs in place: settings,
   presets, scenes, camera profiles and media are kept. The hidden menu items: VJ VIZZIES > "Set up / Update this Mac..."
   re-runs the setup with your current answers.

Install (the zip: scripted, Terminal)
-------------------------------------
   Unzip VJ-VIZZIES-SUITE-<version>.zip, double-click INSTALL.command (or  ./INSTALL.command --yes --machine-name LAPTOP
   --lighting-nic en0 ; preview with --dry-run). Same two questions, same folders; the thin VJ VIZZIES.app (controls only)
   goes to /Applications. With this path the login items are zsh scripts, so the camera permission still needs the one
   Terminal step:  "~/Applications/OATS NDI HUB/oats-cam/cam.sh" restart   from the same Terminal, once, click Allow.
   The same scripts are inside the dmg's app: "/Applications/VJ VIZZIES.app/Contents/Resources/suite/INSTALL.command".

Intel Mac (2020 MacBook Pro)
----------------------------
  The camera suite and the player run as shipped (universal binaries). Only if a future package ever ships an
  Apple-Silicon-only player would the installer offer to compile it (OATS_BUILD_ONLY=player ./m0.sh build --x86, needs the
  Xcode Command Line Tools); with this package it does not ask.
  NDI previs on Intel uses the player's own NDI library ("native": it is the Intel library, no helper, no Rosetta).
  Expect lower fractal detail than on an M-series Mac: the governor keeps the frame rate, not the resolution.

Two machines on one network (the laptop next to the show Mac)
-------------------------------------------------------------
  The show Mac is "OBS.HOST", pinned to its cable. The laptop must NOT be: the installer never copies another Mac's
  name or address, it asks for this Mac's own. With the same name, "OBS.HOST (Link Cam)" would exist twice and
  receivers (Vision, OBS, the hub) see only one of them. Where it lives: OATS NDI HUB/suite.env (+ ndi-config/, rewritten
  at every start by ndi-config.sh) and VJ VIZZIES/oats-m0/m0.env (+ ndi-config/, rewritten by m0.sh at every start).
  Rename later: edit those two files, then  autostart.sh now  in each folder.
  Both players listen on sACN universe 5 and OSC 7000: give the laptop its own universe on the console (or stop one
  player) when both are on the lighting network, and point the PC launcher (windows/) at the Mac you mean.

Use
---
  Player controls   http://<this Mac>:8090  (lighting network only). VJ VIZZIES.app opens the same, with the health dot.
  Player            ~/Applications/VJ VIZZIES/oats-m0/m0.sh status | stop | log ;  autostart.sh now  starts everything
                    (start flags: --no-ndi-meta --universe 5 --ndi helper|native, in autostart.sh)
  Clips             ~/Applications/VJ VIZZIES/media/<bank>/ + library.json: the controls' clip grid uploads into it.
                    make-suite.sh --with-media ships the example library; otherwise media/ starts empty.
  Scenes / looks    oats-m0/scenes.json (an example is seeded), tools/*_presets.json. Show packs: not in this build.
  NDI sources       a layer can show an NDI sender on the LAN (source "ndi", DMX layer source 30-39 picks the n-th source;
                    README "NDI sources"). Optional: oats-m0/ndi_order.json fixes the slot order by name (file-based,
                    kept on update); without it the discovered order is used.
  grandMA3 fixture  gdtf/OATS@OATS VIZ.gdtf (v0.10) next to the player folder: import it into the console's fixture library.
  Hub               http://<this Mac>:7080/  multiview at /multiview, phone tally at /tally. OSC in on 7081.
  Cameras           "OATS NDI HUB/READ ME FIRST.txt": profiles (one per camera, cam.<name>.env), one camera per USB
                    port, close OBSBOT Center / Link Controller, tally modes (HUB_TALLY program|preview|off), the
                    OBSBOT LED tally (CAM_TALLY_LED), the OSC address list.
  Update            "Check for Updates..." in VJ VIZZIES.app, or open a newer dmg's app (zip: INSTALL.command again). Everything of yours is kept.
  Uninstall         "~/Applications/OATS NDI HUB/uninstall.sh" and "~/Applications/VJ VIZZIES/uninstall.sh"; the
                    folders stay for you to delete.
